# Mac 维护与九卷备份

Mac 已接管生产。正式维护、九卷加密备份、Windows 异机副本及使用第二处密钥的独立恢复均已执行；当前版本和最终备份覆盖范围见 [正式切换记录](handoffs/2026-09-09-production-cutover.md)。本页区分实际生产操作与准备期的合成故障演练。

## 维护

生产使用已核验的只读宿主目录：

```text
node scripts/mac/production-maintenance.mjs enter <生产宿主目录>
node scripts/mac/backup-production-state.mjs <生产宿主目录>
node scripts/mac/production-maintenance.mjs resume <生产宿主目录>
```

enter 先核验全部容器身份，写入属于该发布/切换批次的维护标记，再依次停止 guard、OpenClaw、账本。任何停止失败都保留标记，防止自动恢复与维护抢占。resume 只解除匹配的维护标记，要求资源身份、完整输入、主机/Docker 恢复空间均合格；实际启动仍由常规宿主按顺序执行。

存在生产存储故障锁时，resume 会拒绝。维护命令不负责解除该锁，不能用“备份成功”替代跨账本/回执的人工对账。若账本写成功但回执没落盘，重启接收器可能产生重复记账，必须先核对这类未完成操作。

上述生产 CLI 已完成实际停机、备份和显式恢复。崩溃、namespace、低空间和 ENOSPC 矩阵使用隔离三服务环境验证，不在生产数据上制造故障。

## 九卷备份

`backup-production-state.mjs` 要求已有匹配的维护标记、三个已识别服务全部停止、九卷身份及导入凭证合格，并检查所有运行容器均未使用源卷。它不会帮忙停止未知进程，也不会从运行中的卷悄悄抓取快照。

源卷只读挂载，遍历完整文件树并记录内容、权限、uid/gid 和符号链接；SQLite 两库核对所有表及 schema。归档在内存流中使用 AES-256-GCM 加密，完整清单作为附加认证数据。先验证整份密文，再解密到本次新建、无网络的九个校验卷。恢复后再次核对文件及两库，成功才写 verified.json；只删除本次随机校验卷。原卷不会被覆盖，生产维护状态也不会自动解除。

备份在 `~/Library/Application Support/Clawbot/production-backups`，密钥在独立的 `production-backup-keys` 目录，均为本机用户私有。归档预算 20 GiB，保留至少 10 GiB 主机空间并预留两份估算大小；超预算拒绝新增，不自动删旧副本。失败归档保留现场，不标记 verified。本次部署已在 Windows 私有目录保存异机数据副本，并在另一私有目录单独保管第二份密钥；新部署必须自行配置这些目的地。

准备期九卷合成验证通过正常 DELETE 快照及异常退出后含已提交记录的非空 WAL。文件、权限、未知表、索引、64 位整数、BLOB 及 WAL 记录均匹配。真实 Windows 最终快照与 Mac 生产备份另有完整文件／两库审计，不用合成结果代替。

## 测试宿主更新与回退

提交干净源码后运行 `node scripts/mac/publish-host-service.mjs --prepare`，生成不改现有任务的只读候选包；再用 `node scripts/mac/update-test-host.mjs <候选提交>` 安装。工具只允许同一测试镜像，核验旧任务和实际进程，保存原任务副本，等待卸载完成，安装后检查新宿主和页面。失败会恢复旧任务。回退使用同一命令指定先前提交。

`--verify-failure-rollback` 仅用于测试宿主的故障演练：模拟新任务启用后的验证失败，检查是否自动恢复旧版。此流程已实际通过。宿主版本回退不会恢复数据库，也不能用于账本已经发生写入后的跨设备数据回退。

## 独立历史归档恢复

`verify-nine-backup.mjs` 不挂载或依赖原生产卷，仅需要已保存的归档目录、私有密钥和归档记录中的固定 runtime 镜像：

```text
node scripts/mac/verify-nine-backup.mjs <生产备份目录> <私有密钥文件> <镜像sha256>
node scripts/mac/verify-nine-backup.mjs <生产备份目录> <私有密钥文件> <镜像sha256> --retain
```

默认只做恢复校验，结束后移除本次校验卷。`--retain` 保留本次全新且验证通过的九卷候选数据，卷名为 `clawbot-recovery-<随机批次>_<role>`，另在仓库外保存恢复回执。候选卷使用 recovery 标签，不能被生产运行器自动识别或启用。失败不会保留一组被误称“验证通过”的候选；不会覆盖或停止任何原服务。

已对含异常退出 WAL 的历史归档执行独立恢复、保留候选、核验无生产标签，并清理本次合成候选。错误密钥和篡改密文均在创建目标卷之前拒绝。恢复测试与原有在线测试容器互不替代。

## 经核验的复制包

```text
node scripts/mac/copy-verified-backup.mjs <已验证备份目录> <现有私有目标目录> <本机密钥文件>
```

复制工具支持七卷测试和九卷归档。先核验恢复记录和完整密文认证，再独占创建新的复制目录；只复制 state.enc、manifest.json、verified.json，逐文件核对哈希并对目标密文再次认证，成功后写 copy-receipt.json。密钥不会放进复制包，源文件和旧副本不被覆盖。损坏归档在创建目标前拒绝。此工具的本机合成验证与下述实际 SSH 异机恢复分别留证。

异机流程为：通过已核验的 ZeroTier/SSH 将三文件包送到私有目标，核对哈希与访问权限；再下载异机包及单独保存的第二份密钥，调用独立恢复入口验证。本次已实际完成该往返，未以 Mac 原文件代替下载文件。密钥不随普通复制包一起传播；代码和固定镜像也应独立归档。
