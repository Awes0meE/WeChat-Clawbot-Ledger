# Windows 后台启动

正式账本、隔离测试账本和 Ledger Tunnel 使用当前账户、`S4U`、`Limited` 的计划任务，在非交互桌面运行。登录后自动启动，不需要显示控制台，也不保存 Windows 密码。OpenClaw 保留自己的隐藏启动器。

`Settings.Hidden` 只影响任务列表中的显示，不等于隐藏程序窗口。直接关闭控制台可能终止附属服务；应迁移任务的运行会话，而不是关闭窗口来停止进程。

## 安装与迁移

三个安装脚本为新任务创建 `S4U` principal。已有任务仍须先通过精确身份检查；重复运行安装器不会自动替换已有任务或强制重启服务。验收脚本兼容旧的 `Interactive` 与新的 `S4U`，并继续限制同一账户、`Limited`、精确命令和原有重启策略。

迁移已有部署时：

1. 先验证任务路径、完整 action、当前账户 SID、运行级别，以及监听端口的程序路径和显式配置。不得只根据任务名称操作。
2. 先迁移 `18888` 测试账本。只把 principal 的 `LogonType` 改为 `S4U`，将任务 XML 归一化后核对，确保没有其他字段变化。
3. 通过已识别的任务对象停止和启动；确认旧监听退出后才能启动新实例，绝不结束未知进程。检查新进程属于 session 0，且本地健康响应正常。
4. 再迁移正式账本与 Tunnel。Tunnel 须验证已安装脚本哈希、二进制哈希、完整任务 action 和父子关系；停止后须确认 supervisor 与自己的 cloudflared child 均退出，避免启动重复实例。
5. 验证两个账本健康、Tunnel 父子进程均在 session 0、公网登录页以及 OpenClaw Gateway 和微信通道探测。探测期间只输出布尔值、计数和状态码。

任一迁移失败，恢复内存中保留的原 principal，确认无遗留实例后重新启动原任务。不得修改账本、认证文件、Cloudflare 路由，或通过放宽 origin 校验绕过失败。首次启动若尚未就绪，应先检查失败阶段与服务状态，再决定是否重试。

S4U 对网络身份验证和加密文件有访问限制；本部署已验证本地账本和使用自身认证机制的 Tunnel 能在后台运行，不应据此推断其他依赖 Windows 网络凭据的服务也兼容。[Microsoft 任务登录类型说明](https://learn.microsoft.com/en-us/windows/win32/api/taskschd/ne-taskschd-task_logon_type)
