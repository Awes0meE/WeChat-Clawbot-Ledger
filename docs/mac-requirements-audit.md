# Mac 原交接要求核对

2026-09-09，对照 [原交接](../mac-handoff.md) 第 3.3、5、6、7、8 节更新。Mac 独立准备与正式迁移验收均已完成；当前业务和生产看板为 `8a9b796`。完整操作证据见 [正式切换记录](handoffs/2026-09-09-production-cutover.md)，版本与入口见 [当前清单](mac-before-windows-checklist.md)。

## 功能与迁移验收

| 要求 | 已执行证据 | 未覆盖的边界 |
| --- | --- | --- |
| 固定版本与身份 | ARM64 镜像 162 项源码检查、官方 Codex 二进制哈希保持一致；实际生产配置及九卷来源绑定通过 | Intel Mac、Windows Docker 未验证；Windows 保留原生部署 |
| 六工具和所有者 | 同源码候选六工具／八回合、陌生人拒绝；真实唯一微信 owner／游标与最终快照核对 | 不支持自动切换 owner 或账本账户 |
| 明确支出 | 真实直接记账及唯一 API 交易对应通过；分类、金额、日期、餐段与食堂编号有回归 | 无多币种、多账户自动选择 |
| 确认与取消 | 真实 prepare → resolve → 唯一交易，以及 prepare → cancel 零写入通过；自然确认／取消词 37 场景通过 | 含修改或疑问的完整消息不按确认词前缀写入；取消不删除历史交易 |
| 去重与权威回复 | 同 ID 去重、同文本不同 ID、当前消息回复、跨实例和重启由持久化回归验证；实际回执与账本匹配 | 未执行腾讯平台同一 message ID 重放；上游缺 ID 时随机后备无法保证稳定重放键 |
| 查询 | 真实微信历史、精确金额搜索通过；HTTP 汇总、分页和可读回复有自动及模型验收 | 自动化结果不等于所有自然语言表达都实测过 |
| 完整数据与授权 | Windows 最终停服包九卷导入，全文件和账本 16 表／回执 12 表比对；原 secret_key、微信状态保留；官方模型及历史读取通过 | 每个新来源仍须核验实际路径和系统凭据，不能照搬当前机器的私有配置 |
| 公网 | Mac Tunnel 已接管原域名，登录页、安全策略及有效 HTTP/MCP token 公网拒绝通过 | 未更改主站路由；公网可用性依赖 Mac、电源和家庭网络 |
| 唯一生产端 | Windows 四项任务停用、三个服务端口关闭；Mac 三服务启用，旧测试实例已退役 | 未实际重启 Windows；已核验的是禁用的自启动配置 |
| 正式备份 | 最终九卷 11112 项、两库全表恢复比对通过；Windows 副本及第二处密钥下载后再次独立恢复通过 | 不自动删除旧备份；备份后的新写入需要后续备份覆盖 |
| 版本更新 | 真实 9f3c0e5 → 62cfd9e → 4870258 → 8a9b796 均以当时最新数据生成新卷并维护切换，旧卷保留 | 真实 Mac → Windows 反向迁移、同版本历史恢复未执行 |

当前确认词修复的可移植回归为 686 项：685 通过、0 失败、1 跳过；Windows 回执／持久化 141 项通过。先前 Windows 856 项和 Mac 640 项结果属于各自版本，不表述为当前跨平台全量实测。

## 常驻运行与故障边界

| 要求 | 已执行证据 | 当前限制 |
| --- | --- | --- |
| 插电常亮 | AC sleep/display sleep 均为 0；用户选择开盖、插电、屏幕常亮 | 息屏、合盖不在选定运行方式内，未实测 |
| 连续观察 | [181.93 分钟连续健康、零断采](handoffs/2026-09-08-mac-three-hour-observation.md) | 已按用户要求结束三小时验收，不重启 24–48 小时等待 |
| 锁屏／重启 | [实际锁屏](handoffs/2026-09-08-mac-lockscreen-check.md)及[整机重启后人工登录恢复](handoffs/2026-09-08-mac-reboot-check.md)，两库不变 | 保留 FileVault／用户登录依赖，不宣称无人登录恢复 |
| 容器／网络 | 隔离 origin、Gateway、Docker VM 和出站网络故障恢复；生产维护后微信轮询及公网恢复 | 未断家庭路由器验证真实离线补收，不承诺无限保存离线消息 |
| 模型／HTTP／MCP／微信授权 | 实际迁移授权和业务通过；独立诊断、同账户暂存、维护导入和中断接续已隔离验证 | 凭据存在或旧成功日志不等于当前外部授权有效；生产续期／轮换入口未全部实际执行 |
| Tunnel／故障关闭入口 | 固定 origin 身份、进程退出、namespace、网络退化由隔离三服务验证；正式 Tunnel 与维护恢复通过 | 不在生产制造错误源、存储满或强杀故障 |
| 磁盘和存储故障 | 低水位、ENOSPC／SQLITE_FULL、持久故障锁、只读对账与审核解除有回归和隔离演练 | 未模拟物理磁盘损坏；真实存储故障解除尚未执行，不自动恢复数据库 |
| 生产看板 | 18990 真实三服务状态，简洁首页、默认折叠详情；实际宽屏／手机宽度检查通过 | 看板更新与业务版本分开；人工阶段记录不能代替实时健康 |

## 必须保留的状态

原交接中的账本、附件、配置与 secret_key、完整回执 SQLite、独立 HTTP/MCP token、微信账号／配对／游标、OpenClaw/Codex 状态及 Tunnel 配置对应九卷。未知表、索引、触发器、视图和大整数均参与全量核对。

Windows 原始最终快照、旧生产卷、恢复候选、固定镜像与源码、双机正式备份和两处密钥继续保留。跨系统兼容只在经过核验的副本上调整 SQLx 校验值和精确路径，原数据库及历史文件保留；不能通过清空会话、删除 WAL 或关闭校验完成迁移。

本次用户选定的迁移流程已验收完成。表中明确未实测的场景继续作为适用范围，不以合成结果销项，也不无限扩展本轮迁移开发。
