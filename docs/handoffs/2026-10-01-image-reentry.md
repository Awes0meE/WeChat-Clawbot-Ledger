# 图片删账后重新入账

## 原因与修复

用户删除四笔图片账目后重新发图，仍收到重复记账提示。旧逻辑只读取 `image_expense_links` 指向的历史成功回执，没有查当前账本。只读核验确认四笔旧交易均返回 HTTP 400、`success=false`、`errorCode=205001`、`errorMessage=transaction not found`。首次探针缺少时区头，只返回时区错误，不能证明已删除；补齐头后的四项精确结果才是结论依据。

新图片消息遇到旧成功关联时，按旧回执的交易 ID 读取账本。账目存在时继续防重，网页修改不会被误认为删除。只有固定 ezBookkeeping v1.6.1 的明确不存在返回可以解除旧关联；[上游错误定义](https://github.com/mayswind/ezbookkeeping/blob/v1.6.1/pkg/errs/transaction.go)与隔离实测相符。超时、权限错误、其他错误或异常空结果均返回“暂时无法核对……这次没有重新入账”，不会放行写账。

解除仅涉及仍归属于该旧回执的图片和订单关联，保留原 `message_receipts`、永久确认及迁移记录。原消息重放不能再写入；新消息重新接受当前图片金额、币种、时间、权限和原子领取检查。并发核查旧记录不能删除新消息已经取得的关联。没有数据库迁移、历史回执重写或生产自动补录。

## 验证

可移植回归 961 项通过、1 项原有跳过；固定 ARM64 Docker adapter、图片和回执工具测试 215 项通过。测试覆盖原账仍存在、明确删除、网页编辑、权限与时区错误、超时、异常空结果、撤销权限、永久原消息防重、同订单不同图、重启及两个数据库实例并发重发。

独立 18888 账本实际执行写入、删除和新消息重发：删除后恰好新增一笔，原日期与秒数保留，重开回执库后仍正确，旧消息重放及后续重发不能再次写入。再删除并同时发送两个新消息，只产生一笔。所有数据为合成样本，微信通道关闭，无生产写入或手机发送；视觉提取与传输关联未改，本轮没有重复实际模型图片测试。Windows 原生运行仍未重新验收。

私有证据保存在 Clawbot 的 `acceptance/image-reentry-2026-10-01`。初始化首次因现有操作锁繁忙停止，未抢占锁；锁正常释放后初始化成功。首次测试入口参数错误导致脚本未启动，修正入口后完整验收通过。失败记录保留。
