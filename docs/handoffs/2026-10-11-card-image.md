# 卡片消费截图时间误拒修复

本记录是最初两例的定向修复阶段，后续已按用户要求扩展为 [AI 语义校验与 100 组图片测试](../../test-cases/image-semantic/README.md)；下列计数与行为只描述早先阶段。

2026-10-11 完成源码修复；生产仍运行 `f5f1934`，本记录不代表发布或手机验收。

## 失败原因

只读核对 2026-10-10 20:08 +08:00 的两次真实图片请求、工具参数、结果与原图。模型正确提取了各自的 SGD 金额及跨日消费时间，但 `record_expense` 均返回 `rejected / time`，没有执行入账。卡片交易详情中的日期没有“付款时间”等标签，日期与钟点之间另有逗号；原校验器强制要求时间标签，也不接受这个分隔符。

原参数离线重现确认两笔均触发 `image-time`。此外，原校验器不识别卡片交易的 `Status: Approved`，同一参数即使修正时间，仍会被判为需要确认。两张原图、参数及完整模型测试报告保存在本机 Clawbot `acceptance/image-card-2026-10-11` 私有目录，不进入 Git。

## 修复范围

- 图片时间允许无标签的完整年月日及钟点，兼容半角／全角逗号，保留秒数。增加英文 `Transaction time/date` 标签；仍校验日期、钟点与参数一致，拒绝未来时间、无效日期、多时间、物流标签和仅有时分的状态栏时间。
- 当前卡片消费的明确 `Status: Approved` 可与最终 Total 和币种依据共同支持直接记账。退款、未批准、拒绝、撤销继续拒绝；待处理、预授权、冻结继续要求确认，金额或币种歧义不绕过确认。
- 同步工具描述和记账提示，要求无标签时引用原文，不编造时间标签。固定识图配置、官方模型与 harness、工具权限、微信身份、数据库结构和永久去重保持。

没有向生产重放或补录失败消息。生产发布须使用当前数据的九卷备份、独立恢复和既有维护切换流程，不能直接替换正在运行的不可变文件。

## 验证

- 旧实现对两组真实参数均拒绝时间并要求付款确认；新实现均保留原时间且无需额外确认。
- 便携完整回归：1084 通过，1 项既有跳过，0 失败。
- 图片与回执工具：本机 189/189；固定 ARM64 OpenClaw 环境 189/189。覆盖无标签日期、逗号、秒数、跨日、错误时间、付款状态、一次写入与重复图片防重。
- ARM64 首次测试受镜像的 isolated-test 环境变量影响而触发部署配置门禁；清除该单元测试进程的环境选择，并挂载共享工具入口后通过。没有挂载生产数据或接入生产网络；真实 Linux 包装器由隔离模型测试另验。
- 实际模型测试初始化因旧生产 seed 授权过期而停止；只读核验当前本机官方 Codex 授权属于同一账户后，仅复制到本轮空的隔离授权卷。未更换或刷新生产授权，测试微信通道关闭。

首轮两张原图的实际官方模型测试 4/4 通过：两笔各写一次且日期、时分正确，两次重复发送没有新增交易。但该轮发现隔离初始化仍使用 8000/16000 字符上限，而当前 AGENTS.md 已超出单文件限制；不能把该轮视为完整规则验收。生产配置只读核验为 12000/24000，未发生此项配置变更。

隔离初始化及刷新现对齐 12000/24000；测试入口在运行前检查四个实际提示文件的长度，拒绝截断。复验准备期间，临时清理脚本的查询缺少账户过滤而被 API 拒绝，未执行删除；随后的模型重跑被主动停止，不计入通过。补齐查询后，仅删除与本轮成功回执的 ID、金额及时间逐项匹配的两条隔离交易，保留回执和图片关联，因此最终原图复验也覆盖删账后重发。

最终使用 `clawbot-message-acceptance:card-image-20261011-final`，官方 `gpt-5.6-sol` 与 Codex harness 的原图复验 4/4 全通过：两笔各新增一条正确原币金额、原日期及原时分的交易；两次重发均返回防重且零写入。四次回复均匹配当前消息的权威回执，没有微信真实发送。完整提示长度检查通过，模型日志无截断警告；镜像内五个关键文件与最终源码逐项 SHA-256 一致。

完整测试报告已导出到私有证据目录。核验归属后删除本轮一个隔离账本容器、七个测试卷（含测试授权与图片副本）、测试网络及一个中间测试镜像；最终候选镜像和验收资料保留。清理前后生产三容器 ID、镜像、启动时间和重启计数完全相同，三项服务健康。临时操作脚本已移除，生产备份、旧卷与运行文件未触及。
