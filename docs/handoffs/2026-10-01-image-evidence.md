# 图片币种与付款证据误拒修复

## 真实失败与原因

用户在删账重发修复上线后，再次发送四张订单截图，四次均返回“实付款、币种或付款状态还不能确定”。本轮读取该次真实工具调用并核对当前原图：四笔金额和创建日期、秒数均提取正确，截图均有待发货状态和最终实付款；旧图片防重并非此次拒绝原因。

四次实际 `currencyEvidence` 均使用“页面金额使用¥，支付方式为支付宝支付，订单为中国电商页面”。旧校验只接受按固定顺序出现的“中文……电商/购物……订单”，因此全部抛出 `image-currency`，被外层统一成笼统提示。只纠正币种再复验，又发现付款证据采用“支付方式……实付款”而没有复述“待发货”，旧词表会把模型明确的 `paid` 降为待确认。原图、真实参数、订单标识和会话证据全部保留在 Git 外，公开测试使用合成金额。

## 改动与边界

中国、国内、大陆或中文等上下文，与电商、购物或订单依据及 ¥ 的组合不再要求固定语序；继续拒绝只有符号、只有支付宝支付方式、日元或日本上下文的不明人民币推断。支付方式本身仍不能证明已付；模型明确判断 `paid`、最终金额有“实付款/实际支付/amount paid”依据且没有未付、失败或退款状态时，可以直接入账。明确负面状态优先，`unclear` 和其他金额、币种歧义继续拟单确认。

币种字段说明同时明确“判断的币种 + 图片依据”，例如“CNY：中国电商订单、¥”；不要求原图印有 ISO 代码。前置识图也保留币种判断与依据，避免模型已经选中 CNY 却只返回符号或付款方式，随后被校验层误拒。只有共享符号或依据冲突时仍必须标为歧义。

运行提示要求优先引用订单状态，区分退款操作按钮与实际退款。境外收货地不改变截图标示币种。原始来源、金额一致性、日期秒数、权限、旧消息永久防重和删除后重发规则保持。

完整原图首轮还发现四笔均正确写入金额，但使用了收图时间。仅补记账提示后复验仍失败，继续读取模型实际输入才确认：固定 OpenClaw 的 Codex 图像理解先把像素转成描述，默认任务是“Describe the image.”；描述保留商品和金额，却省略创建时间。后续记账轮只收到了这段文字，没有日期可提取。不能把该问题描述为记账模型看见原图却故意忽略日期。

新增明确的 `tools.media.image` 契约，沿用当前官方 Codex 和 `gpt-5.6-sol`，不覆盖模型选择：要求前置图像理解保留最终实付款、币种依据、实际付款状态、订单信息中的完整消费日期与时分秒；物流时间分开，收货人、地址、电话和支付流水号不转述。输出上限 6000 字符。记账工具说明也明确区分图片与纯文字时间规则。解析、秒数保存和未来时间限制不变。

Mac 更新流程仅在原图像理解配置为空时添加这一精确配置，并同步 guard 中的配置哈希；已有自定义或禁用配置拒绝覆盖。原有模型、六工具、所有者、路由、令牌与数据库保持。测试初始化和 Windows 脱敏模板使用同一契约；Windows 原生执行仍待独立验证。这是现有官方识图步骤的提示与输出长度修复，没有增加其他模型提供商或修改官方 harness。

拒绝信息现在分别指出币种、最终实付款或付款/退款状态问题，工具详情及运行日志只保留固定原因代码，不输出图片内容或身份信息。没有自动补录生产历史请求。
