# 历史明细原始 JSON 故障与系统复核（2026-09-07）

## 根因与修复

14:00 的实际微信历史查询成功取得三笔支出，但最终回复是原生 MCP 返回的一整行 JSON。该结果不是查账失败：运行提示词要求所有工具文本逐字回复，而原生历史查询返回结构化数据；已有的固定格式回复保护只覆盖五个自定义工具，没有覆盖原生历史工具。此前一次成功的微信查询没有保证后续每轮都按相同格式回答。

`expense-history.mjs` 核验原生 MCP 的文本或 SDK `details.structuredContent` 包络，将有效支出整理为时间、SGD 金额、分类、备注的编号列表。调用 hook 固定配置账户和支出类型，默认三笔、上限十笔，补齐展示字段；结果 hook 校验时间、金额、账户、币种和分页完整性。缺失、异常及不完整结果统一说明未取得可靠明细，不发送底层错误或原始 JSON。

历史查询的可信来源和规范化参数通过按运行、调用标识区分的 SQLite handoff 交给结果 hook，再经持久化回复交给微信发送实例。提示词明确区分 `exec` 内传回工具结果与微信最终回复。交易备注只作数据展示，不能触发写入。
