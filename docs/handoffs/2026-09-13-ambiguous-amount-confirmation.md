## 最终行为

- 明确的一笔支出仍可直接入账。F1 商品名与数量不作为额外价格，保留 NTUC8.25、食堂编号、日期、加法和币种检查。
- 多个可疑金额由既有 OpenClaw AI 按消费语义选择最可能的实付金额，再调用 `prepare_expense`。插件不按位置或数值大小排序，候选必须匹配当前可信原文的完整金额或明确加法合计。
- `record_expense` 收到有依据但不唯一的候选时，直接进入既有持久化确认流程，无需模型在已消费的可信绑定上重试工具。
- 确认单完整列出账本、原币金额、一级／二级分类、备注及原消息消费时间。拟单阶段没有账本 API 请求。
- “是”才按已保存候选写入一次；“不是”、新实质消息或十分钟超时不写入。跨插件实例仍保持原消息、原时间、去重和权威回执约束。
- 无原文金额依据、错误时间／币种／分类、数量／日期／原价／余额、显式备注中的数字和注入文本仍受原门禁约束；新增完整数字边界避免将三位小数拆成可拟单金额。

后续按用户决定扩展为全部 159 种原币子账户、单条多问题回复及中行现汇卖出价。最终日程为每天 00:00 Asia/Singapore 一次，不是每 30 分钟。用户最初的“折为 SGD 再存”决定已被“按原币存子账户、查询换算”取代。详细字段、每日持久化缓存、失败规则和账户准备脚本见 [多币种与汇率](../multicurrency-and-rates.md)。

隔离开发阶段没有修改模型、上游版本、原回执库表、生产账户、六工具权限或生产数据；随后上线的账户新增详见上述回执。新增独立汇率缓存 DB 和后台服务，Windows 发布白名单与对应夹具同步保留。真实 API 验收只在全新合成账本 18888 进行。
