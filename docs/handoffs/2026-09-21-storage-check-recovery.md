## 已确认的故障链

- 15:22:33.917 宿主保存存储故障锁，随后依次停止 guard、OpenClaw、账本。OpenClaw 记录正常退出；停机前各服务最近的健康检查通过。
- 18:19 检查时 Docker 可用，但三个业务容器停止，宿主保持 `storage-fault-latched`。故障锁让正常恢复的存储采样也无法自动启动服务。
- `storageDecision` 把缺失样本、任何采样错误及非法数值都判为 `fault`。真正的低空间阈值走另一条 `stopped-low-disk` 分支，因此不能把本次锁定直接解释为磁盘满。
- `managed-docker-driver.mjs` 的命令失败会丢弃原始错误，存储采样再统一返回 `STORAGE_UNAVAILABLE`；故障文件只记身份和时间，不保存采样、异常阶段或退出信息。
- 宿主先 inspect 再决定是否采样，而控制器又 inspect 一次。如果第一次暂时不可用、第二次恢复正常，也可能将缺失的存储样本锁定为故障。这是代码可达路径，不是已经证实的本次触发路径。

使用内存中的模拟 driver 核对了缺失样本、`STORAGE_UNAVAILABLE` 和 `STORAGE_IDENTITY_INVALID`：一次失败均可锁定停机，随后正常容量样本也保持锁定。没有在生产注入故障。

**原始采样失败的具体原因仍未知。** 当前检查恢复正常不代表已永久修复。不能把 Docker 超时、2 GB 内存或合盖休眠写成确定根因。
