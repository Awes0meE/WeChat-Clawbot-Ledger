## 样本与规则

[当前来源清单](../image-semantic/public-sources.json)含 100 个不同 SHA-256：80 张公开网页原图、20 张 SROIE 真实扫描小票，0 张生成或重绘图片。图片保存在 Git 外；公开清单仅含来源、哈希、人工预期和理由。已排除已知模板、演示占位图、伪造教程及同一交易的重复照片。网上公开并不构成银行鉴真。

当前人工预期为 61 张入账、39 张零写入。单笔已发生支出的实际金额与日期明确即可记录，缺用途写字面值“无”、不追问用途；成功向他人转出也可记录。缺日期先补日期，缺币种默认 SGD；收入、退款、未付和本人账户间划转不新增支出。平台、样式及覆盖数量见[用例说明](../image-semantic/README.md)。这不是所有场景的穷尽，也不是随机抽样准确率。

## 验证方法

固定官方 `gpt-5.6-sol` / Codex harness、OpenClaw 2026.8.2 与 ARM64 隔离账本。使用真实图片前置理解、可信消息关联、工具执行、实际 HTTP 写入和最终回复链路；微信发送由测试入口截获。每图核对新增行数、金额、币种、日期、可见时分秒、指定的备注和类别，以及当前消息权威回执。人工另外审查分类和追问理由，零写入或自动通过不自动等于语义正确。

首轮使用冻结的原始预期；后续人工修订和模型失败分别记录。首轮冻结集含 C126，主集后来以空备注银行转账 B05 替换该重复类型的裁切日期照片，替换发生在首轮 C126 执行前。最终主集须另行验证 B05，不能直接借首轮总数声称同一批 100 张全部通过。

## 首轮发现与改动

- C012、C091、S04、S12：月份、日期或分钟数字被读错，实际账本日期错误。识图提示增加原像素关键字符复核，不让常识补成确定数字。
- C031：商品单价被当成实际总额。要求实付依据或完整且唯一的结算构成，不能因为数量为一就假设运费和折扣为零。
- C049：旧截图“昨天”被按收图当天换算。要求图内或本条用户补充给出截图日期；服务期间、下一次续费日期也不能替代本次付款日期。
- S08：24小时制下午钟点后重复标 PM 被当成冲突；按实际含义规范，不能机械地拒绝冗余格式。
- C092：选了开单时间而非底部结清时间。前置描述需保留各时间角色，优先付款或结清。
- C114、S03、S05：法国及马来西亚小票常用短日期被过度认定歧义，甚至要求确认年份世纪。按图内语言、地区和票据习惯解释，不把任意数字重排视为同等候选。
- C013、C024、C075、S01、S04：广告、家用磨豆机、企业订阅、黏土与书包被不合理分类。按实际商品或服务选择，目录没有合适类别时使用其他支出。
- C069：虽然零写入，但把收款收入称为支出并要求选择一笔。补强付款人与收款人视角判断。

人工预期也有三处修订：C034 完整结算唯一得到实付金额，不能仅因合计标签裁切而拒绝；C052 只有可能属于下次续费的更新日期，不能认定本次付款时间；C104 地域信息被遮挡且短日期有歧义，原来指定 USD 与具体日期过度推断。原始失败不删除，修订后的实际结果单列。C104 首轮回复断言 CAD 也缺可见依据，需独立复核。

## 原图复核

仅强化提示没有消除 C012、C091、S04、S12 的像素误读。相同官方模型的独立结构化读取中，内存放大后的四张均读到人工核对的日期/钟点；原始文件未修改。源码因此新增写入前复核，重新检查附件哈希与当前消息授权，独立读取完整账目；失败时不写账，不退回旧猜测。该诊断不是最终端到端通过证明，完整链路结果另列。

C052 的 Apple 订阅项目旁更新日期不能直接视为本次付款日；Apple 的 [Receipt Fields](https://developer.apple.com/library/archive/releasenotes/General/ValidateAppStoreReceipt/Chapters/ReceiptFields.html)区分购买时间与订阅期限，[renewalDate](https://developer.apple.com/documentation/appstoreserverapi/renewaldate)描述续订时间。对于该裁切图，缺少独立本次收据日期，保持询问日期的预期。

第三轮仍有 C091 月份误读、C034 结算过度拒绝和 B05 无用途转账被拟单，不能把单次诊断通过当作修复完成。后续实现改为全图加三块覆盖完整长边、彼此重叠的细节图，避免只放大整图后小字仍难读；另明确完整小计/运费/总优惠可唯一计算，不重复扣优惠子项。细节副本只在内存生成，不修改 100 张原件，也不以合成图替代原件。

第四轮使用行为提交 `33a66da271c24fb1c7c47917ac723b21a08bbcb8`，实际隔离镜像的 11 个关键运行文件与源码哈希一致。冻结用例 SHA-256 为 `418de1089e1fc6f3802fad71dc5d47f31e943573b4aa2459c89403ef4bdebee2`。所有模型轮次独占隔离状态；重测前只删除经回执逐行核对的隔离测试交易，保留原回执、防重记录与原始报告，不操作生产账本。

第四轮发现的四处时间与交易判断问题保留原始失败：C022 把电商发货后的成交完成时间当成购买时间；C044 把底部税控凭证时间替代上方明确的交易时间；C072 采用对方收款时间而非本人转出时间；C059 仅因先买后付就要求贷款还款凭证。前三项需按本人交易及时间角色选择，不能按页面位置或时间先后选择；已成交的信用购物也不能和待付款订单混同。相应源码修正已准备，须另行复验，不能借旧镜像结果声称已通过。

C096 的地区和币种未出现在裁切图中，原先仅凭 Walmart 品牌指定 USD 和 2020-01-11 的人工预期不成立。现改为询问短日期的月日顺序；缺币种按 SGD，补充日期后应可入账。第四轮虽默认 SGD，却猜了具体日期，按修订预期仍失败；冻结结果和当时的自动错误项保留。当前主集因此为 61 入账、39 零写入，正例 13 种币种。

C086 前置识图耗尽 60 秒后，仍在同一运输端图片处理范围内，却因沿用文字提示相关窗口而丢失可信消息关联。源码仅允许精确匹配运输端消息、账号、发送者与文件路径的图片沿用既有十分钟入站有效期；超期、错误身份、已结束 run 及后续写前授权检查保持，文字相关窗口不变。

第四轮另有 C114 与 C086 相同的慢识图关联问题；S09 清晰的现金支付、零找零与小计/税额/明确舍入能交叉确认 112.45 MYR，却被拒绝。新增完整现金结算交叉核对规则，不允许任意舍入、重复计税或把现金递交额直接当消费额。

自动通过之外，人工发现 C098 在地区被遮挡时断言 USD，C120 与 B03 追问并非必填的币种，以及 B01 忽略明确的 `raja cell` 交易备注而写“无”。修正要求跨国品牌不能单独决定币种或短日期顺序；缺币种按 SGD；可见交易备注即使是简称也应保留。B01 增加实际账本备注包含值断言。
